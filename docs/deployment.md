# 运行与部署

[返回首页](../README.md) · [开发说明](development.md)

## 本地开发预览（默认标准版）

安装 Node.js 22 或更新版本，在仓库根目录运行：

```bash
npm start
```

打开 `http://127.0.0.1:4173`。服务器只监听本机。Windows 可双击 `scripts/启动Afterword.cmd`；请勿直接双击 HTML。

## Cloudflare Pages

自行使用推荐免费社区版；运营者需要保留高级授权校验时选择标准版。两者共用部署步骤。连接自己的 GitHub 仓库，选择以下配置：

| 设置 | 免费社区版（自行使用） | 标准版（保留授权） |
| --- | --- | --- |
| 框架预设 | None | None |
| 根目录 | 仓库根目录 | 仓库根目录 |
| 构建命令 | `npm test && npm run build:community` | `npm test && npm run build` |
| 输出目录 | `dist` | `dist` |
| Node.js | 22 或更新 | 22 或更新 |

构建时不需要任何 API Key 或签发私钥。不要把用户 Key 添加到环境变量或 GitHub Secrets。用户在自己的浏览器页面填写 Key。

`dist` 仅包含网站静态文件和响应头配置。源码目录 `src` 不是最终发布目录。Pages 会读取生成的 `_headers`，设置 CSP 等响应头。默认 `noindex` 仅请求不收录，不是访问密码。

## 1Panel 或其他静态托管

社区版运行 `npm run build:community`；标准版运行 `npm run build`。将 **dist 内的文件** 上传到网站运行目录，使 `index.html` 直接位于网站根目录。启用有效 HTTPS。无需配置 Node 服务、数据库或反向代理。

非 Pages 服务器通常不会识别 `_headers`，需在服务器中配置对应响应头。不要把整个源码仓库当成网站运行目录。

## 免费社区版

部署时运行 `npm run build:community`。如果需要一个可独立在本机运行的社区目录：

```bash
npm run community
cd community
npm start
```

标准版的公开测试许可证仅供开发验证，不可出售。正式收费前需单独更换公钥并建立受控签发流程；私钥不可进入本仓库。

## 更新与域名

更新前先导出加密备份，保留可回退的版本。保持同一协议、域名、浏览器和存储标识时，更换托管不需要主动迁移记录；预览地址和其他域名的数据是隔离的。

使用新域名时，请先从旧域名导出，再在新域名恢复，并重新设置 Key、主题和授权。不要立即把旧域名强制跳转，也不要清除网站数据。

真实手机网络、浏览器跨域策略、真实 ZIP 导出和余额查询需要实际验证；构建成功不能代替这些检查。

## 部署可授权的标准版

使用 `npm test && npm run build`，输出目录 `dist`，环境变量 `NODE_VERSION=22`。不要使用 `build:community`，后者会直接开放所有高级功能。两种构建的图片、语音与联网入口均免费；DeepSeek API 的费用由用户自行承担。

标准版保留离线 license 校验，但目前只配有公开测试公钥和测试授权，不能据此销售正式授权。上线收费前需要：

1. 在独立受控环境生成正式 ECDSA P-256 签名密钥，只把**公钥**写入 `src/build-config.mjs`，再构建部署。私钥、真实客户信息和签发记录不得提交到 GitHub 或 Pages。
2. 建立独立签发流程，使用与现有 `license.mjs` 兼容的格式；确认测试授权在正式公钥下不能通过，正式授权的有效期与签名验证正常。
3. 单独确定收款、交付与售后方式。本仓库没有支付、兑换码服务或客户端强防破解保障；公开社区源码允许技术用户自行免费构建完整版。

浏览器录音需要 HTTPS 和麦克风权限；从旧部署更新时同步更新静态文件与 `_headers`，确保 `media-src` 允许本地 `blob:` 音频，工作线程脚本来自本站。无需添加其他第三方域名。
